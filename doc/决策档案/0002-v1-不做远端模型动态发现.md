# 0002 — v1 不做远端模型动态发现

## 状态

已采纳（2026-07）

## 上下文

火山方舟 Agent Plan 的管控面接口 `ListArkAgentPlanModel`（`POST /?Action=ListArkAgentPlanModel&Version=2024-01-01`）可以列出套餐内模型，但：

- 需要火山引擎管控面 AK/SK 与 HMAC-SHA256 签名，与数据面使用的 Bearer API Key 不是同一套凭据。
- 响应只返回 `{ ModelID }`，不含 context window、max output、vision、thinking 等能力元数据，Pi 需要的模型能力仍要另外维护。
- 本机只读探测数据面 `GET /api/plan/v3/models` 返回 `404`（2026-07-21），数据面没有替代的发现入口。

## 决策

v1 使用静态已验证模型目录，不接入管控面动态发现。

## 理由

1. 动态发现需要额外的管控面凭据与签名实现，把一个数据面 provider 扩展成跨产品线的管控面客户端。
2. 动态发现也拿不到能力元数据，Pi 的模型注册仍要人工维护，收益不覆盖成本。
3. 静态目录可用官方套餐文档与人工验证核对，与 `doc/20-能力参考/` 的现行事实一致。

## 后果

- 模型增删需要人工更新 `index.ts` 的 `MODELS` 与 `doc/20-能力参考/火山方舟-Agent-Plan-接口事实.md`，并记录在 `CHANGELOG.md`。
- 套餐端个别模型的限额差异，通过本机 `models.json` 覆盖层处理，不进扩展。
- 若未来要动态发现，需另立决策：包括管控面凭据来源、签名实现归属与能力元数据的补充来源。
